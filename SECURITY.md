# Security policy

Report suspected vulnerabilities privately through [1904's contact form](https://1904.ai/contact). Identify the product as **1904 Desktop** and mention if the issue also affects the hosted dashboard. Keep vulnerability details out of public issues, pull requests, and comments.

Include the affected version and operating system, steps to reproduce the issue, and the impact you observed. Redact account details, session cookies, tokens, and private task content. If the report needs sensitive material, request a secure way to share it.

Please coordinate public disclosure with the maintainers so they can investigate and address the issue.

## What the app can do on your computer

1904 Desktop shows the hosted dashboard in a sandboxed window. With **Use My Computer**, it can also run shell commands on your computer for a task’s agent. That feature is off until you choose **1904 → Use My Computer…** and confirm. Every rule below is enforced on your computer, so it holds even if the cloud side is compromised. Once connected:

- **Origin.** 1904 Desktop answers a request only for a message its own window sent within the last six hours (it stamps each one with a proof made from a per-computer key the page never sees), or inside away mode you started on this computer for that task. Anything else is refused without a prompt.
- **What the stamp guarantees.** The dashboard page is served by 1904, so a script on it can send a message too. 1904 Desktop therefore stamps a message only when you pressed a key or clicked in its window within the previous 10 seconds and the window is in front; the app sees that input itself, and events a page makes up do not count. Anything else leaves unstamped and is noted in this computer’s log. So a message counts as sent from this computer only while you are actively using 1904 Desktop’s window. It does not prove you wrote that message: a compromised page could send its own in those seconds. Every command it leads to still needs your approval on this computer and runs in the sandbox.
- **Approval.** Every command waits for your approval in a native prompt on this computer that shows all of it, unless "Allow for this message" covers it, or it came from a message sent elsewhere inside away mode. Nothing a web page or 1904 sends can approve it for you, and settings on 1904 never do. A command too long to show in full is never run. "Allow for this message" ends when the task moves on to another message, and after 30 minutes at most. An approved command starts only after 1904 confirms the request still stands.
- **Sandbox (macOS).** By default a command runs under `sandbox-exec` with a profile that denies everything and then allows only: running and forking programs, signals to its own processes, named system facts, semaphores and shared memory, a short named list of system services, reading the system (not the home folder, other drives or other apps’ temporary files), reading the app’s folder, its own temporary folder and named toolchain folders, and writing the app’s folder and its temporary folder. In the app’s folder it cannot write `.git` itself, git’s settings, hooks and attributes, editor task folders, `.envrc` or `.pre-commit-config.yaml`. Credential stores, Keychains and 1904 Desktop’s own data come last and win over every allowance, for reading and writing. It cannot send Apple events, open apps, files or links, start background jobs, write preferences, mount disks, or use the pasteboard or the window server. No path is ever written into the profile text; each is passed to `sandbox-exec` as a parameter, so a folder name cannot add a rule. The app’s folder can never be, contain, or sit inside a credential store, 1904 Desktop’s data, `~/Library` or a hidden folder in the home folder; saved folder choices are checked again every time they are read.
- **Network.** A sandboxed command has no network unless you allow it in the prompt. With it, it can reach the internet but not loopback services on this computer, and can listen on loopback only; a service listening on all of this computer’s addresses may still be reachable through its network address. Network off is not a privacy control: a command’s output returns to 1904, so whatever it can read can reach 1904 that way.
- **Limits of the sandbox.** Files a sandboxed command writes in the app’s folder are code: they run with your full permissions when you or your tools run them later outside the sandbox, so review them first. A process a command deliberately detaches (with `setsid` or a double fork) can outlive the command; it stays inside the sandbox.
- **Full access.** A command that asks for full access runs as the user signed in to this computer, with that user’s permissions, files, keys and network. It is asked about every time with a second confirmation (Touch ID, or a dialog that defaults to Cancel), and is never covered by "Allow for this message" or away mode.
- **Windows.** 1904 Desktop has no sandbox on Windows yet, so every Windows command is treated as full access, and away mode is not offered. A background process a Windows command starts can keep running after the command exits, because `taskkill /T` cannot follow a parent that has already exited. On macOS, background processes a command starts end with it.
- **Environment.** A command never inherits 1904 Desktop’s environment: it gets `PATH`, `HOME`, `USER`, `LOGNAME`, `SHELL`, `LANG`/`LC_*`, `TERM` and its own temporary folder (on Windows, the system variables Windows needs), and shells start without startup files.
- **Away mode** is started only on this computer, for one task, for at most 8 hours and a command budget, after native questions and Touch ID; without Touch ID, a last question names 1904’s own title for the task and the limits, and Cancel ends it at once. Started from the dashboard page, it also needs your recent key press or click in the window. It covers sandboxed commands from messages sent elsewhere only; a message from this window always asks. 1904 can end it but never start or extend it.
- **Keys.** The token and proof key 1904 issues for this computer are kept in the app’s data folder, encrypted with the system key store (Keychain on macOS, DPAPI on Windows) through Electron `safeStorage`. Without that storage, the computer is not connected. Only the app’s main process reads them.
- **The page.** The dashboard page can only ask whether this computer is connected or paused, open the connect prompt, and open the away-mode questions. It cannot run or approve a command, read output, or read either key.
- **Controls.** **Pause Use My Computer** in the 1904 menu stops all requests. 1904 Desktop keeps its own log of every command, decision and the end of its output on this computer. **Disconnect This Computer…** asks 1904 to revoke the token and deletes the keys from this computer, even when 1904 can’t be reached; disconnecting in 1904 Settings also revokes it.

The [README](README.md#use-my-computer) describes the feature in full. Reports of a way to run a command without the person’s approval or outside the sandbox, to approve one from a web page or from 1904, to make a request pass the origin check, or to read the token or proof key are in scope and especially welcome.
